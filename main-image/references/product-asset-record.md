# 制作与导出

## 商品资产档案与创意边界

主图与详情页使用同一款色档案；可单独运行任一流程，也可在同一任务目录复用。先分开回答三类问题：

1. **商品事实**：用户文字、原图可见内容、已核实规格。每条事实关联来源和状态。不可见结构、功能和尺寸保持未知，直到用户补充或授权按常见外观做 AI 示意。
2. **商品视觉锚点**：挑 6–8 个最能辨认该款的特征，例如外轮廓、比例、关键部件位置、色泽、纹理、标识和接缝。不同参考图标明身份、机位、局部、人物或风格用途。品牌标识与实售配件单独锁定；禁止生成相似品牌标记或臆造包装内容。
3. **创作空间**：已确认的卖点可以转写成短文案，场景、光线、机位和版面可根据目标自行设计；不得把创作空间扩展成新增商品事实。平台、合规和用户明确的限制优先于风格表达。

实拍图先保留原片，再清理背景得到无字白底基准；白底图保留原文件并另提取主体。对透明边、纱网、毛发、玻璃反光和深浅交界逐处检查。所有新视角由商品档案约束，可见部分保持一致；用户授权推演的隐藏结构明确标注 AI 示意。交付档案要能追溯每张图使用了哪些原图、裁切、机位和事实。

逐图提示词应让生成工具完成有设计意图的成品：先锁商品身份，再描述这一张要回答的买家问题、镜头与画面路径、背景空间、文案字级、标注或图标与商品的关系。保持足够创意空间，不把所有屏做成同一版式；规格、型号、中文固定文案等高精度元素可用可编辑文字层排版。图片本身必须包含需要交付的完整设计，不能把单独商品照和外置说明拼成“已完成”。

## 共用商品记录

需要交成品、做套图或续做时，在当前任务目录保存 `product.json` 和制作清单，以便两个流程使用同一依据。字段按任务填写。

- `products` 记录商品或变体的 `id`、名称、可用资料和素材清单。每个素材有 `id`、文件路径、用途和适用变体。
- 每条 `facts` 带 `id`、确认后的内容、来源及状态（`visible`、`confirmed` 或 `unknown`）。来源指向具体的素材编号、规格资料或用户给出的说明。成品中只使用 `visible` 或 `confirmed` 的事实。
- 视觉规范记录色板、光线、背景、排版层级和适用载体。拍摄视角和构图按单图说明。
- 制作清单按张记录模块编号、用途、对应变体、素材编号、事实编号、目标规格和结果路径。续做时核对哪些成品已存在且可用。

## 主图

按「主角是谁、买家看哪里、靠什么证据」写每张图的简报，同时确定取景、背景、留白和文案位置。保留品牌本身的可见标识。需要准确呈现包装、实物颜色、接缝或端口时，选真实素材的对应角度和局部。源图背景干净时可直接用实拍排版。需要编辑时，把商品源图或经核对的商品素材给当前宿主的图片工具，写清每张参考图的作用。背景与使用氛围可发挥，实物形态和已核实的部件保持一致。含人物的多张图需要同一身份时，使用同一已认可的人物参考。

比对源图和成品，发现用于展示的实物细节变化时，返修该张，或改用实拍与排版。生图工具不可用时，先检查能否使用实拍、已有素材和本地排版完成。逐张导出前按文案清单校验正式文字和数值。

## 详情页

1. 按产品问题和证据选模块。常用候选为首屏、购买理由、细节证据、实用场景、用法与安装、变体选择、规格与包含物。可根据商品增减或调整顺序。
2. 用户提供或指定版式图时，先读取该图的实际像素。长图可分段查看并保留原图坐标。记录区块顺序、图框相对位置、尺寸、间距和字体层级。把识图推断的数值作为估算。用户需要精确对齐时，用指定的版式图和 HTML 截图逐段比对可测量的边界。用本商品的已核实素材和文案填充版面。
3. 用实际照片或经检查的生成素材填图，以 HTML/CSS 渲染文案、参数表和排版。只要线框时可用语义明确的占位框，并将缺失信息留在内部说明。成品页用可用素材替换占位框。图片用本地相对路径或内嵌数据，交付 HTML 时一并提供它引用的本地素材。使用本地字体或系统字体栈，检查实际渲染和文字换行。

## 由 HTML 导出 PNG

适用于详情页模块，也可用于已排版的等宽主图。使用 Node.js、可加载的 Playwright 和本机 Chrome、Edge 或 Playwright Chromium。脚本以指定的 CSS 画布宽度逐模块输出同像素宽的 PNG。只要可编辑方案时，直接交付 HTML。

在每个需要导出的、互不嵌套的模块根节点上加 `data-export-id`。ID 由小写字母、数字和短横线组成。文档顺序就是导出顺序。同次导出的模块设置相同宽度，模块间距和外围装饰可留在 HTML 预览中。页面示意如下，`{{...}}` 在实际任务中替换为已核实的内容。

```html
<!doctype html>
<html lang="zh-CN">
<meta charset="utf-8">
<style>
  * { box-sizing: border-box; }
  body { margin: 0; overflow-wrap: anywhere; font-family: "Microsoft YaHei", "PingFang SC", sans-serif; }
  [data-export-id] { width: 100%; padding: 48px; background: #f4f4ef; color: #18241d; }
  img { display: block; width: 100%; height: auto; }
</style>
<main>
  <section data-export-id="hero">
    <h1>{{商品名称}}</h1>
    <img src="assets/hero.png" alt="商品全貌">
  </section>
  <section data-export-id="specifications">
    <h2>商品规格</h2>
    <dl><dt>{{参数名}}</dt><dd>{{已确认值}}</dd></dl>
  </section>
</main>
</html>
```

从工作目录运行，脚本路径指向本 Skill 中的文件。将示例中的 `750` 换成本次需要的实际宽度。

```powershell
node '<技能目录>/scripts/export-panels.cjs' './detail.html' './detail-images' 750
```

脚本可直接使用环境中的 Playwright，也会检查 Codex 随 Node 安装的相邻模块目录。使用其他位置的 Chrome/Edge 时将浏览器可执行文件路径传给 `ECO_VISUAL_BROWSER`。脚本按区块编号导出 PNG，并生成 `manifest.json` 记录实测尺寸。每次完整导出使用新的成品目录，或只按新清单交付列出的文件。导出后打开首图、最长文字模块和包含规格的模块检查版面，并查看整页的顺序。没有可用渲染环境时，交付可编辑 HTML 与素材并说明切片状态。
